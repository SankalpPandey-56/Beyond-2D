1. Executive Architectural Overview

BEYOND - 2D bridges the gap between static 2D blueprint drawings and real-time interactive 3D spaces. While the front end provides a photorealistic Three.js WebGL viewport with filmic shading, material swatches, and a mobile walkthrough mode, the entire analytical intelligence, geometric math, and computer vision pipeline is implemented 100% in Python.

Python was selected over Node.js and C++ for the algorithmic core due to its unparalleled numerical computing ecosystem (OpenCV, NumPy, Shapely 2.0, and Trimesh), which allows sub-50ms vector and topological matrix computation.

2. Module-by-Module Technical Deep-Dive

FastAPI ASGI / Uvicorn Port 8001

Module 1: API Gateway & Microservice Layer

Primary Files: backend-python/app/main.py, backend-python/app/api/routes.py

⚙️ Logic Implemented
  • Asynchronous routing (async def) running on Uvicorn ASGI engine.
  • Accepts both multipart form files (UploadFile) and JSON Base64 strings.
  • Strict type enforcement and schema validation using Pydantic v2 data models.
  • Auto-generates interactive OpenAPI documentation at /docs.
💡 Why This Logic? (Why Not Flask / Django?)
  • Why not Django? Django is a heavyweight MVC monolith with an ORM and session tables. For an algorithmic image pipeline, it adds >150MB of unnecessary memory overhead and slow cold-starts.
  • Why not Flask? Flask is synchronous by default. During CPU-heavy OpenCV transformations or network AI calls, a Flask thread blocks the entire worker process, preventing concurrent user requests.
OpenCV NumPy Aspect Ratio

Module 2: Computer Vision Preprocessing & Footprint Isolation

Primary File: backend-python/app/services/image_preprocessing.py

⚙️ Logic Implemented
  • Grayscale & Adaptive Inversion: Converts drawings into high-contrast binary masks where walls are white ($255$) and negative space is black ($0$).
  • Outer Footprint Isolation: Scans wall pixel distribution to establish the physical building bounding box [bx, by, bw, bh], mathematically separating walls from outer dimension text.
  • Footprint Cropping: Crops image tightly to structural exterior walls so normalized coordinates ($0.0$ to $1.0$) represent the real building perimeter.
💡 Why This Logic? (Why Not Hough Transform / Raw AI?)
  • Why not Hough Transform (cv2.HoughLinesP)? Blueprints are covered in dimension lines, measurement arrows, and annotations. Hough lines detect hundreds of false "walls", turning the drawing into chaotic wireframe noise.
  • Why not feed raw uncropped image to AI? Giving uncropped images with white margins causes AI models to hallucinate exterior walls and misalign coordinates with canvas borders.
Gemini Vision AI JPEG Optimization Zero Hallucination

Module 3: Dual-Image Vision AI Interpretation

Primary File: backend-python/app/services/ai_interpretation.py

⚙️ Logic Implemented
  • Dual-Image Strategy: Passes Image 1 (Full Blueprint) for dimension text extraction and Image 2 (Cropped Footprint) for precise spatial room and opening coordinates.
  • Compression Pipeline: Downscales raw 4K PNGs to $1024\text{px}$ JPEG ($85\%$ quality), shrinking payloads from $3.5\text{MB}$ to $\approx 64\text{KB}$ ($98\%$ reduction) to completely eliminate socket write timeouts.
  • Negative Opening Rules: Explicitly forbids generating windows on solid walls, verifies bathrooms have zero windows unless drawn, and forbids kitchen-washroom doors.
💡 Why This Logic? (Why Not Tesseract OCR / Pure 3D Diffusion?)
  • Why not Tesseract OCR? Tesseract fails on rotated, small, or stylized architectural text labels and has zero concept of spatial containment.
  • Why not 3D Generative Diffusion (e.g. Point-E)? 3D diffusion models produce deformed, wavy, organic meshes that violate architectural rectilinear constraints and cannot provide metric dimensions.
Shapely 2.0 Planar Graph 100% Watertight

Module 4: Deterministic Planar Geometry Engine

Primary File: backend-python/app/services/dynamic_geometry.py

⚙️ Logic Implemented
  • Exterior Perimeter Loop: Mathematically derived as the topological boundary of the union of room polygon boxes:
    footprint = unary_union(polys).boundary
  • Flush Interior Partitions: Derived from pairwise polygon boundary intersections:
    partition = polyA.boundary.intersection(polyB.boundary)
  • Orthogonal Opening Projection: Vector projection $t = \frac{\vec{w} \cdot \vec{u}}{L^2}$ clamps openings to $[0.15, 0.85]$, preventing corner collisions.
  • Sanitary Constraint: Enforces FORBIDDEN_DOOR_PAIRS, mathematically preventing doors between Kitchen and Bathroom.
💡 Why This Logic? (Why Not Let LLM Output Walls?)
  • Why not let AI output walls directly? LLMs are inaccurate with floating-point decimals. If an AI returns Wall 1: [0.0, 0.0] -> [5.01, 0.0] and Wall 2: [4.98, 0.0] -> [4.98, 4.0], the walls fail to meet at the corner, creating severe light leaks and non-manifold holes in 3D.
  • Why Shapely Planar Geometry won: Shapely executes C++ GEOS planar topology. Adjoining rooms are mathematically guaranteed to share flush, zero-void partitions.
Morphological Closing Connected Components Offline Fallback

Module 5: Deterministic Room Recovery Fallback

Primary File: backend-python/app/services/pipeline.py

⚙️ Logic Implemented
  • Applies morphological closing with a large $25 \times 25$ rectangular kernel (cv2.morphologyEx(thresh, cv2.MORPH_CLOSE, kernel)) prior to connected component labeling.
  • Filters connected components with an area threshold $\ge 5\%$ of the total footprint area.
  • Snaps adjacent room coordinates flush against each other to remove micro-gaps.
💡 Why This Logic? (Why Did Naive Connected Components Fail?)
  • Why standard contour finding fails: Doorways are drawn as open gaps in walls. Standard connected components "leaks" through the open doorways into hallways and bedrooms, merging the house into one giant blob or fragmenting it into 20+ tiny 1m² tiles.
  • Why Morphological Closing won: The $25 \times 25$ closing kernel acts like "closing all interior doors" before analysis, sealing each room into a watertight box so OpenCV extracts clean, distinct rooms.
Trimesh glTF 2.0 / GLB PlanPop CAD

Module 6: 3D Mesh Synthesis & Binary GLB Compilation

Primary File: backend-python/app/services/mesh_generation.py

⚙️ Logic Implemented
  • Polygon Extrusion: Extrudes floor slabs downward ($0.08\text{m}$) and wall prisms upward ($2.80\text{m}$).
  • Coordinate Transformation: Applies an $X$-axis rotation ($R_x(90^\circ)$) converting 2D cartesian coordinates into 3D OpenGL standard ($Y$-up, $X$-East/West, $Z$-North/South).
  • Binary glTF Compilation: Emits compliant binary .glb files embedding vertex normals, UVs, and PlanPop CAD vertex colors.
💡 Why This Logic? (Why Not Headless Blender `bpy`?)
  • Why not headless Blender? Running Blender via Python (bpy) requires a massive 500MB server installation, takes 3–5 seconds to boot per request, consumes gigabytes of RAM, and crashes in headless Linux server environments.
  • Why Trimesh won: Trimesh is a lightweight, pure-Python / C-NumPy geometry library. It generates and compiles the entire 3D building scene in under 20 milliseconds with near-zero memory footprint.
